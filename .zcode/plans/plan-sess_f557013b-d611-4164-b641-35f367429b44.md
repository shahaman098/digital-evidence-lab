# Digital Evidence Lab v0.2 — Advanced Upgrade

## Context
The repo is a 253-line stdlib-only forensic exercise (`evidence_lab.py` with collect/verify/timeline). The user wants it "advanced" across three chosen axes: **deeper analysis & reporting**, **broader evidence parsers**, and **performance & packaging polish** — keeping the **stdlib-only, zero-install** constraint. Custody/signing upgrades are explicitly out of scope. Collection/verification file formats stay compatible (case schema `digital-evidence-lab.case.v1` unchanged); error message strings that existing tests assert on are preserved.

## 2. Parsers (`parsers.py`) — registry replaces hard-coded format branch

Each parser yields canonical rows `{timestamp, action, detail, extra}`; provenance (`source`, `source_record`, `source_sha256`) added by the timeline orchestrator as today.

- **Field mapping**: `--mapping mapping.json` — exact-name or `*.ext` glob keys → `{"timestamp": col, "action": col, "detail": col, "extra": [cols]}`. Auto-detection fallback (timestamp-candidate key names + value sniffing via `datetime.fromisoformat`); the mapping actually used (explicit or auto-detected per file) is recorded in the report.
- **SQLite multi-table discovery**: iterate user tables from `sqlite_master`; per table pick timestamp-ish column (name match or sampled values parse as aware ISO), action/detail columns by name heuristics or first-fit; `source_record` = `table#rowid` (single-table case keeps plain integer rowid); opens read-only immutable as today.
- **mbox** (`mailbox.mbox` + `email.utils.parsedate_to_datetime`): timestamp from `Date`, detail from subject/from/to; extra: `message_id`, `from`, `to`, `subject`.
- **Syslog**: RFC 5424 lines natively (tz-aware ISO timestamps); RFC 3164 supported only with new `--assume-offset +HH:MM` / `--assume-year YYYY` flags — assumptions disclosed in report `timestamp_assumptions`.
- **Apache/nginx combined log**: regex; format carries tz offset.
- **gzip / zip members**: `.gz` streams to the inner parser chosen by the stripped name; `.zip` parses each member (`source` = `archive.zip!member.csv`), CRC-verified, encrypted zips rejected with a clear error.
- Unknown formats still listed in `unsupported_files`, never analysed.

## 3. Analysis (`analysis.py`) — driven by new `timeline` flags

- `--keywords "a,b"` / `--keywords-file f` / `--regex`: case-insensitive match across action/detail/extra; report gets per-term counts + matching records (capped at 100) with provenance.
- Entity extraction (always on, reported): IPv4, email, URL, domain, 64-hex hash via regexes → unique values, occurrence counts, first/last seen, example provenance.
- `--session-gap SECONDS`: sessionize sorted records; report sessions (start/end/count) + largest gaps.
- Summary stats: records per source/action, per-hour UTC histogram.

## 4. Reporting (`reporting.py`)

- `report.json` v2: adds `schema: "digital-evidence-lab.report.v2"`, `analysis` (keywords/entities/sessions/histogram/counts), `field_mappings`, `timestamp_assumptions`, `file_classifications`; keeps all existing keys (`case_id, records, unsupported_files, integrity, ...`).
- **Hash-set sidecar**: `timeline --hashset known.csv` (columns `sha256,label[,notes]`) → manifest files classified known/labeled in `file_classifications`.
- `report.html`: single self-contained file, inline CSS + inline **SVG** charts (records/hour bar chart, per-source, per-action), summary + timeline table (capped), keyword/entity/session sections, disclaimer footer. All values `html.escape`d, no JS, no external assets. Written by default; `--no-html` skips it.
- `timeline.json/csv` row shape unchanged (6 provenance keys; optional `extra` dict only when mapping/parser supplies one). CSV formula neutralization preserved.
- New `search` subcommand: `evidence_lab search CASE QUERY [--regex]` → verify, parse, keyword-match, print JSON result.

## 5. Performance & CLI polish

- `--jobs N` (default 1) for `collect`, `verify`, `timeline`; thread-parallel digests via shared `digest_many`; deterministic ordering regardless of jobs.
- `--verbose` progress lines to stderr; `--version`; clean error handling widened in `cli.py` (catch `json.JSONDecodeError`/`TypeError` paths surfaced today as tracebacks).
